## 2. Designated Student Programming Task: The Event Repetition Diagnostic Engine

To establish authentic student technical contribution, Pardhu must independently implement (or substantively refactor and verify) **Task 1: The Event Repetition & Coverage Diagnostic Engine** in `src/engine/evidence.ts`.

### Task Specification:
- **Module:** `src/engine/evidence.ts` -> `assessRepetition()` and cycle event grouping.
- **Objective:** Evaluate light curve observations across predicted transit cycles $[cycle_{\text{min}}, cycle_{\text{max}}]$ and determine whether a signal represents genuine periodic repetition, a single transient dropout, or unobserved gaps.
- **Contract:**
  ```ts
  export interface EventDetail {
    cycle: number;
    centerTime: number;
    sampleCount: number;
    isSampled: boolean;
    meanFlux?: number;
    depth?: number;
  }
  ```
- **Crucial Edge Cases to Handle:**
  1. **Telescope Downlink Gaps:** A predicted transit cycle has 0 observations. It must be counted as an unsampled gap, NOT an observed absence of a dip.
  2. **Sampled Flat Baseline:** A predicted transit cycle contains measurements ($N \ge 2$), but the star is flat ($\text{depth} \approx 0$). This is an observed non-event (the star was observed not to transit).
  3. **The Single-Event Trap (Case C):** Exactly 1 transit event exhibits significant dimming; all other predicted cycles are either gaps or flat baseline. Phase folding at harmonic periods can produce an attractive fold, but `repetition` status must be returned as `inconclusive`, warning: *"Only 1 single transit event has observations! Phase-folding on a single event can produce an artificially neat alignment without proving any repetition."*
  4. **True Periodic Repetition (Case A):** Multiple separated transit cycles exhibit consistent dimming depths. When observed events $\ge 3$, return `measured` status.
- **Independent Test Harness:** An independent test suite is provided in `tests/student_repetition.test.ts` for Pardhu to run and verify his code.
